## 对前序结论的更正

`MusicClient.playlists()` 原型把 playlist/detail/all 当作歌单列表查询，实际缺少必填 playListID。去掉空值后服务明确返回：queryPlayListDetail 的 playListID 必填。这是调用理解错误，不能归因于账号权限或歌单不存在。

该方法应改为明确的单歌单详情方法；在找到正确列表协议或得到可核对的真实歌单样本前，不承诺“我的歌单”完整可用。

官方公开 H5 中 queryUserCollectList 的内容类型至少包含歌曲 1、歌单 4、自建歌单 5、榜单 7；本轮通过本人 SNS ID 调用，仍只有歌曲返回。空列表不构成功能成功或失败的充分判据。

## 播放与权限

本轮标准样本没有 auditionTime 字段，完成有限大小下载和全曲 FFmpeg 解码，之后删除临时音频。

本人收藏样本元数据包含会员音质信息，服务响应包含可访问的资源 URL，同时包含试听字段。这些字段是否表示当前授权限制、通用曲目信息或需要其他客户端播放上下文尚未厘清。没有强行忽略试听字段，也没有整首下载会员样本。需要进一步确认正常授权播放请求的参数与返回语义，再验证会员完整播放。

fileInfos 中还出现 JSON 类型资源，与 fileURL 的音频资源不同，客户端不能把 fileInfos 中第一个 URL 直接当作音频。

## 重现

- `scripts/audit-features.mjs`：核心只读接口及结构摘要。
- 本地 `research/audit-personal.mjs`：收藏分页、分类、播放资源响应检查。
- 本地 `research/audit-media.py`：普通样本完整解码、会员样本文件头、歌词/封面。
- 本地 `research/audit-variants.mjs`、`audit-daily-final.mjs`：有限的已知路径参数变体验证。

**结论：基础读取可行，但“我的歌单、每日推荐、会员完整播放”仍是必须解决的三项门槛。不能宣布所有核心功能已验证，也不应据此开始大规模界面开发。**

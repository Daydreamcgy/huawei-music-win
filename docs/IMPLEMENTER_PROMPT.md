## 固定选型

Electron + React + TypeScript，electron-vite + electron-builder，普通 CSS + CSS 变量。三端桌面共用代码，Windows 优先验收。音频首版使用 Chromium 的单个 HTMLAudioElement，系统凭据存储用 Electron safeStorage。

不再询问用户选框架；不使用 Tauri、Go、Rust、Qt、libmpv 或自建后端。若 M1 真实证据证明选定路线无法完成，提交最小复现与具体替代建议，不擅自换栈。

## 当前真实状态

接手前先读 `IMPLEMENTATION_STATUS.md`；下列协议成果仍有效，但不能替代当前桌面验收记录。

- 本人扫码授权、音乐会话兑换、关闭浏览器后恢复访问已验证。
- 收藏/歌单/历史/搜索/专辑/歌手等已取得真实数据。
- 收藏增删、临时歌单创建/简介修改/删除已验证，并清理恢复。
- 当前会员账号一个样本的 MP3/FLAC 全曲及末尾 seek 解码通过。
- 已有 Electron 客户端：真实本人扫码/首屏收藏通过；本地合成 MP3/FLAC 播放、页面/业务/965 首分页自动化通过；华为 CDN 真实全曲与系统安全存储重启仍未验收。
- 先用 Linux 验证共享 API/本地逻辑/UI，不用 Windows 或 Wine 阻塞开发。Linux AppImage 内部包可构建，三端最终验收仍分开记录。
- 自动续期未打通，音乐会话可能约 7 天但未实测到期。不要承诺永久免扫码，也不要每小时让用户登录。
- 每日推荐暂缓。歌单改名/曲目编辑/封面、特殊音质不在首版承诺范围。

## 实施方式

严格按 IMPLEMENTATION_PLAN 的 M0→M6 推进。每阶段先列出短检查表，再实现并运行测试，不要一次写完所有页面才运行。

优先完成 M0 与 M1：安全 Electron 空壳、官方登录窗口、严格回调与凭据保存、重启读取个人收藏、单 Audio 播放 MP3/FLAC 与 seek。M1 不通就停在具体问题上修，不做假数据首页掩盖。

协议逻辑在主进程，renderer 只能调用固定 preload API；远程登录页无 preload、无 Node、无业务 IPC。不要将 token/Cookie/账号完整响应交给 renderer。

页面信息结构遵循方案；最终视觉方向尚未选定，正式美术阶段先给用户看可比较预览，再定风格。不要因此阻塞 M0/M1。

## 安全与权限

- `.local/` 有真实凭据，不得读取打印、复制上传或作为打包资源；`research/` 有私有原始响应，不提交不打包。
- 不自动用研究凭据登录产品，不自动跑真实账号写入脚本。联网个人测试要用户本人授权，写操作只在明确授权范围内使用临时对象并清理。
- 禁止把参数错误、断网、HTTP 400 一律判为登录失效。
- Linux safeStorage basic_text/不可用时只保留内存会话并提示，禁止静默明文降级。
- 写操作超时不能盲重试；先核对服务端真实状态。
- 不复制无许可证第三方代码、不提取应用私密 client_secret、不替换音乐平台音源。
- 不发布 public 仓库/安装包、不上传日志、不注册抢占全局 hms:// 协议。

## 每阶段交付

- 改动清单和可运行命令。
- 单元测试/类型检查/构建结果。
- 实测系统及路径，哪些仅 mock、哪些真实账号、哪些没设备验证。
- 若修改了真实账号，提供恢复检查结果。
- 在 `docs/IMPLEMENTATION_STATUS.md` 维护 M0–M6 的 pending/in-progress/verified 状态和证据，不复制整份计划。

不要只返回计划。读取后先执行 M0；然后推进到你能验证的下一个阶段。唯一需要等待用户的环节是本人登录授权、写操作额外授权、视觉选择、发布身份/证书以及确实缺少的平台设备。

# 华为音乐桌面端 · 窗口宽度两端布局评审

- 评审对象：`docs/review/960|1322|2048` 截图 + `src/renderer/styles.css`
- 方法：960 与 2048 的 10 个页面全部看，1322 抽查 01/03/06/09；下文坐标与宽度均为截图像素实测（1x）。
- 范围：只谈布局、列宽、留白。不改 JSX，不提配色/字体/圆角/新组件，改动全部能落到现有 CSS 上。

## 1. 总体判断

骨架（232 侧栏 / 52 标题栏 / 76 播放条）是稳的，30 张截图没有一张是结构错了，错的都是"内容列没有统一收口"。现在 `.screen` 放到 1680、`.track-list` 收在 1240、`.settings-screen` 收在 900、`.card-grid` 用 auto-fill 不封顶，四个右边界互不相干，于是 960 挤、1322 将就、2048 散。960 只有两处硬伤：音乐厅歌手横向裁边、原生滚动条横在名字下面。1322 作为基准基本可用，只有"最近播放"卡宽比网格小 28px、最后一张被裁 38px。2048 问题最集中：封面 9 列 162（比默认窗小 13%）、收藏列表右侧空 360、设置页标题左跳 64，正好对应用户说的"全屏缩小"和"设置不居中"。把页面列收到 1320，并让卡片、列表、设置都挂到这条列上，P0 全部消失，不需要改 JSX。

## 2. 问题清单

### P0 必须修

#### P0-1 卡片网格在最大化时反而缩小成 9 列 ×162

- **页面 + 尺寸**：我的歌单、音乐厅「我的歌单 / 收藏精选」、首页「我的收藏」@2048
- **现象**：`.card-grid` 是 `repeat(auto-fill, minmax(155px, 1fr))`，页宽 1600 时算出 9 列、每张封面 161.8px；默认窗 1322 下是 5 列 185.6px，最小窗 960 下是 4 列 159px。窗口从 1322 拉到 2048，封面反而缩了 13%，一行从 5 张变 9 张。
- **为什么不好**：最大化本该让封面更大；162px 的封面在这个尺寸下读不出图，直接违背"封面当主角"。
- **改法**：把列数写死，并把页面列收口。

```css
:root {
  --content-max: 1400px;   /* 内容列 = 1400 - 80 padding = 1320 */
  --card-gap: 18px;
}

.screen { max-width: var(--content-max); }

.card-grid {
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 22px var(--card-gap);
}
@media (min-width: 1274px) { .card-grid { grid-template-columns: repeat(5, minmax(0, 1fr)); } }
@media (min-width: 1468px) { .card-grid { grid-template-columns: repeat(6, minmax(0, 1fr)); } }
```

同时删掉 `@media (max-width:1120px)` 里的 `.card-grid { minmax(136px,1fr) }`（现 1551–1553 行），否则它会盖掉新的 4 列规则。改完 2048 是 6 列 ×205，1322 仍是 5 列 ×185.6，960 仍是 4 列 ×159。

#### P0-2 收藏/搜索/歌单详情：列表 1240 左对齐，比页头少 360px

- **页面 + 尺寸**：我的收藏 @2048（搜索、歌单详情同）
- **现象**：内容列是 335–1935，`.track-list` 被 `max-width:1240px` 收在 335–1575；页头「播放全部」按钮右缘在 1935，比列表右缘多出 360px。搜索页没有右侧按钮，但 1575 之后同样空 360px。
- **为什么不好**：列表和它自己的页头不在同一条右基线上，宽屏下整页读起来是"左半边有内容、右半边空"。
- **改法**：把收口从列表挪到页面列，让列表吃满 `.screen` 的内容宽度。

```css
.track-list { max-width: none; }
```

`.screen` 已经是 1400/居中，列表随之变成 1320，页头按钮、行、专辑列、心在同一右边界。专辑列仍保持 `minmax(0, 320px)`，不会继续甩远。

#### P0-3 设置页在宽屏下比其它页左移 64px，且只有 820 宽

- **页面 + 尺寸**：设置 @2048（top 与滚到底两屏同一问题）
- **现象**：其它页标题左起 337，设置页标题左起 **273**（差 64px）；设置块宽 820（273–1093），而同页内容列是 335–1935，右侧空 842px。1322 下（273 起、820 宽）是正常的，问题只在 >1642 出现。
- **为什么不好**：切到设置时整页标题向左跳 64px，右侧一大片空，是"设置不居中"最直接的来源。
- **改法**：删掉 `.settings-screen` 的独立收口，让它继承 `.screen` 的页列；宽度收在表单组上。

```css
/* 删除 .settings-screen 的 max-width:900px / margin-left:0 / margin-right:auto */
.settings-group,
.settings-note { max-width: 820px; }
```

设置页因此与其它页共用同一条左右基线；820 的阅读宽度不变，1322 和 960 的表现完全不动。

#### P0-4 最近播放：卡片行与网格两套尺寸，且 1322/2048 裁掉半张封面

- **页面 + 尺寸**：首页 @1322、@2048（最近播放）
- **现象**：`.card-row` 的 `clamp(158px, 11vw, 190px)` 与网格不是一套：1322 下卡片 158、网格 185.6；2048 下卡片 190、网格 161.8。1322 第 6 张从 x=1152 起、被内容右缘 1272 切断 38px；2048 第 8 张从 x=1791 起、被 1935 切断 46px，两张都露半张封面。
- **为什么不好**：同一页两种卡宽，右边缘硬裁半张图，看起来像 overflow 没处理。
- **改法**：用"整列铺满"替换 clamp，与 `.card-grid` 的列数同步。

```css
.card-row { grid-auto-columns: calc((100% - 3 * var(--card-gap)) / 4); }
@media (min-width: 1274px) { .card-row { grid-auto-columns: calc((100% - 4 * var(--card-gap)) / 5); } }
@media (min-width: 1468px) { .card-row { grid-auto-columns: calc((100% - 5 * var(--card-gap)) / 6); } }
```

960 → 4×159，1322 → 5×185.6，2048 → 6×205，与网格逐像素一致，最后一张不再被裁。

### P1 应该修

#### P1-1 全屏播放页固定 1080/320，越放大越像缩略图

- **页面 + 尺寸**：全屏播放 @2048
- **现象**：`.player-head/.player-body/.player-foot` 都是 `max-width:1080px`，封面 `max-width:320px`；2048 下左右各空 484px，封面 320 只占窗口高的 29%（1322 下同样的 320 占 38%），歌词栏只有 612px。
- **为什么不好**：全屏是"封面当主角"最该成立的一屏，现在封面尺寸和默认窗完全一样。
- **改法**：只在大屏抬高播放页的列宽与封面，1322/960 不动。

```css
@media (min-width: 1600px) {
  .player-head,
  .player-body,
  .player-foot { max-width: 1240px; }
  .player-body { grid-template-columns: minmax(0, 360px) minmax(0, 1fr); gap: 72px; }
  .player-cover { max-width: 360px; }
}
```

#### P1-2 音乐厅 @960：第 7 个歌手只露一条边，滚动条压在名字下

- **页面 + 尺寸**：音乐厅 @960
- **现象**：8 个 96px 圆封面 + 18px 间距共 894px，容器只有 690px；第 7 个从 x≈916 开始，只剩不到 15px 露在内容右缘；`.artist-row` 还保留了 10px 原生横向滚动条，横在歌手名下面（约 232–764），像一条下划线。
- **为什么不好**：贴边露半张脸 + 一条灰色滚动条，是这一档最不干净的一处。
- **改法**：隐藏滚动条，用 28px 渐隐把"还有更多"交代清楚。

```css
.artist-row { scrollbar-width: none; }
.artist-row::-webkit-scrollbar { display: none; }

@media (max-width: 1120px) {
  .artist-row {
    -webkit-mask-image: linear-gradient(90deg, #000 calc(100% - 28px), transparent);
    mask-image: linear-gradient(90deg, #000 calc(100% - 28px), transparent);
  }
}
```

如果不想保留横向滚动，可改 `flex-wrap: wrap; overflow-x: visible; row-gap: 14px`，960 下会排成 6+2 两行。

### P2 可选

- **首页 @2048 · 继续听大图**：1320×208 是 6.35:1，只能看到封面高度的 15.8%（1322 是 20.5%，960 是 30%）。加 `@media (min-width:1642px){ .hero{ min-height:270px } }`，比例回到默认窗的 4.9:1（可见 20.5%）；再想更像"封面"就要在右侧放方形封面，属于加结构，本次不建议。
- **页面切换时 4–5px 横移**：`.main` 的 10px 滚动条在短页面（如 2048 我的歌单）不出现，长页面出现，内容列在 337 与 341 之间跳。`.main { scrollbar-gutter: stable; }` 一次解决，也是上面断点数值成立的前提。
- **音乐厅 @2048 · 最近常听**：8 个歌手占 894/1320（68%），右侧空 426px。`@media (min-width:1600px){ .artist-row{ justify-content: space-between } }` 可拉齐，代价是 8 个时圆间距约 79px，若嫌稀疏可不做。

## 3. 响应式方案

### 断点表

断点由"内容列"推出：侧栏 232 + 滚动条 10 + 左右 40；176px 是卡片下限（默认窗 186 的 95%）。

| 视口宽度 | 侧栏 | 内容列 | 卡片 / 最近播放 | 歌曲列表列 | 播放页 | 设置表单 |
| --- | --- | --- | --- | --- | --- | --- |
| 960–1120 | 204 | 690–850（padding 28） | 4 列，159–199 | `30 44 minmax(0,1fr) 160 30`，gap 10 | 260 + 36 | 690（跟随） |
| 1121–1273 | 232 | 799–951 | 4 列，186–224 | `34 44 minmax(0,1fr) 320 32`，gap 12 | 340 + 64，1080 | 820 |
| 1274–1467 | 232 | 952–1145 | 5 列，176–215 | 同上 | 同上 | 820 |
| 1468–1641 | 232 | 1146–1319 | 6 列，176–205 | 同上 | 同上 | 820 |
| ≥1642 | 232 | 1320 固定，居中 | 6 列，205 | 同上（列表吃满 1320） | 1240 / 360 / 72（≥1600） | 820 |

- 1274 处 4→5 列、1468 处 5→6 列，正是 `n*176+(n-1)*18` 的临界点；这也是不把下限再压低的原因（压低会让 1322 直接变 6 列 158）。
- 960–1120 一档 4 列会低于 176 下限（159），这是最小窗的密度取舍，保留。

### 每个断点隐藏什么、列数、留白

- **960–1120（最小窗）**：不隐藏任何列。专辑列 320→160 已经够用，960 下标题列仍有 346px；卡片 4 列、留白上 22 / 侧 28 / 下 30。若未来允许 <900，再隐藏 `.track-album`（`display:none`）并把列改成 `30px 44px minmax(0,1fr) 30px`，不要现在就砍。
- **1121–1641（默认窗在这一档）**：卡片 4→6 列随视口增长，留白 26 / 40 / 36；侧栏 232。这一段不加横向留白，内容列已经接近满宽。
- **≥1642（最大化）**：内容列锁 1320 并居中，两侧留 40 padding + auto margin（2048 下实际各 203），卡片 6 列 ×205，hero 270，播放页 1240。隐藏项仍然为零。
- 所有断点下都保持：卡片间距 18，行间距 22，section 间距 34，页面标题与第一行内容同一条左基线。

## 4. 居中与留白的结论

- **宽屏内容列应当居中**，不是左对齐。侧栏固定 232 后，左对齐会在 2048 留下一条 360+ 的右空带；居中后 2048 的内容列为 475–1795，左右各 203，视觉重量回到中间，且与标题栏搜索、播放条不冲突。
- **`.screen` 的 max-width 取 1400**（内容 1320）。1680 会得到 9 列 162，比默认窗还小；1320 正好是 6 列 205，封面比默认窗 186 大 10%，符合"封面当主角"。
- **大屏卡片列数上限 6，单卡上限 205**（由 1320 内容列决定，不需要额外 max）。7 列会回到 189 并让一行过挤；6 列在 2K 上是"看得清封面"和"一屏有内容"的平衡点。
- **列表与页头共用同一条 1320 右边界**，列表自身不再收口；专辑列 320 上限保留，避免列宽失衡。
- **设置表单 820 左对齐于内容列，不单独居中**。如果整块居中，2048 下标题会比其它页右移 250px，切页时更跳；表单页右侧留白是正常的阅读宽度，不是缺陷。
- **播放页在 ≤1599 保持 1080 居中**（这一档它是最稳的），只在 ≥1600 抬到 1240。
- **960 的 28px 侧边距是对的**，不要再压到 20；最小窗的问题在垂直密度，不在左右。

## 5. 不要动的部分

- **骨架数值**：`--sidebar: 232px`、`--titlebar: 52px`、`--playerbar: 76px`；以及 ≤1120 时侧栏 204 的这条规则。2048 下侧栏不跟着变宽是刻意的。
- **标题栏**：搜索框右对齐（240，≤1120 时 190）与 42×30 的三枚窗口按钮。它不属于内容列，不要拉去和 1320 对齐。
- **播放条**：`1fr auto 1fr` 的三段式、传输键永远在窗口正中、76px 高度和 36px 的迷你封面。"克制"就靠这个，不要加宽或塞进度信息。
- **hero 的构成**：封面当整块背景 + 左侧压暗渐变 + 208 最小高度（本次只在大屏加高到 270），不要改成左右两栏卡片，也不要加边框。
- **卡片**：1:1 封面、`--radius-lg`、13/11.5 的字号、hover 上浮 3px 和右下播放气泡。只改列数，不改卡片本身。
- **歌曲行**：56px 行高、44px 封面、hover 才出现的播放键与 EQ、`.track-row` 的 5 列结构和 320 的专辑上限。960 下的 `30 44 1fr 160 30` 不用再调。
- **设置行**：14px 上下 padding、1px `--line` 分隔线、右侧控件 `margin-left:auto`；1322 下 820 的宽度不要再拉满。
- **全屏播放页结构**：左封面右歌词、8vh 的歌词上下留白、上下渐隐 mask、1080 的列。这些在 960/1322 都是对的，只在大屏抬列宽。
- **960 的设置页满宽（690）**：这是正确的，不要为了"和宽屏一致"给 960 也套 820 上限。
- **已经对齐的东西**：1322 的「播放全部」与列表右缘、960 的侧栏与内容 28px 间距、各页 section 间距 34、页面标题与首行同一基线。改列宽时别把这几条基准线碰掉。
